Introduction to Comparison Operators

Conditionals, or conditional statements, are a fundamental feature in programming that allow a program to make decisions. These statements function as logical "forks in the road," determining which lines of code should execute based on the answers to specific questions.

To ask these questions, Python provides a suite of built-in comparison operators. While most are familiar from mathematics, their representation on a keyboard requires specific syntax.

Operator Meaning
> Greater than
>= Greater than or equal to
< Less than
<= Less than or equal to
== Equal to (Equality)
!= Not equal to
Standard Python comparison operators and their mathematical equivalents.
Caution
It is easy to confuse = with ==. In Python, a single equal sign (=) is the assignment operator, used to copy a value from the right into a variable on the left. To compare two values for equality, you must use the double equal sign (==).

The final operator, !=, represents "not equal to." The exclamation point (often called a "bang") followed by an equal sign allows you to check if a value is different from another. To utilize these symbols for decision-making, we introduce the if keyword.

The if Keyword and Boolean Expressions

The if keyword allows Python to execute a block of code only if a specific condition is met. This condition is technically known as a Boolean expression—a question that results in a binary answer: True or False. Because there are only two possible outcomes, it is straightforward for the computer to decide whether to "do this" or "not do this."

Let's begin by creating a program called compare.py that prompts the user for two integers and compares them.

compare.py
x = int(input("What's x? "))
y = int(input("What's y? "))
We prompt the user for input and immediately convert the strings to integers.
Initializing variables for comparison.

To compare these variables, we use the if statement. Note the syntax: the statement ends with a colon (:), and the subsequent line is indented. This indentation tells Python that the code "belongs" to that specific if block.

compare.py
x = int(input("What's x? "))
y = int(input("What's y? "))
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
The colon and the four-space indentation are mandatory in Python to define blocks of code.
Adding the first conditional check.

We can expand this script to cover all three mathematical possibilities: less than, greater than, or equal to.

compare.py
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
if x > y:
    print("x is greater than y")
if x == y:
    print("x is equal to y")
We add checks for greater than and equality. Note the use of == for the comparison.
Evaluating multiple independent conditions.

When we run this program, Python evaluates every if statement sequentially from top to bottom.

user@terminal:~$ python compare.py
What's x? 1
What's y? 2
x is less than y

While the program is correct, its design is inefficient. To understand why, we can visualize the control flow—the path the computer takes through the code—using a flowchart.

In this design, the program must check every single diamond (question), even if it already found a "True" answer in the first block.
Flowchart for sequential if statements.

As the flowchart illustrates, the program asks three questions regardless of the inputs. If x is less than y, we already know it cannot be greater than or equal to y. Asking those additional questions is repetitive and unnecessary.

The elif Keyword for Mutually Exclusive Logic

To improve our program's design, we can use the elif keyword. Short for "else if," elif allows us to chain questions together. This creates mutually exclusive conditions: once Python finds a "True" answer, it skips all subsequent elif blocks in that chain and moves to the end of the conditional sequence.

compare.py
if x < y:
    print("x is less than y")
if x > y:
    print("x is greater than y")
if x == y:
    print("x is equal to y")
if x < y:
    print("x is less than y")
elif x > y:
    print("x is greater than y")
elif x == y:
    print("x is equal to y")
By changing 'if' to 'elif', we tell Python to stop asking questions as soon as one condition evaluates to True.
Refactoring for mutual exclusivity using elif.

This optimization becomes clear when comparing the flowcharts. In the new version, a "True" result leads the program directly to the end, avoiding the redundant question diamonds.

The program now terminates earlier in "True" scenarios, making it logically more efficient.
Optimized control flow with mutually exclusive elif checks.

While the difference in speed is imperceptible in such a small script, this foundation is essential for writing efficient, well-designed code as programs grow in complexity and scale.

The else Keyword as a Catch-all

When designing logic, we can often improve our code by identifying scenarios where a question no longer needs to be asked. In our comparison program, we previously used three distinct conditions to check if x was less than, greater than, or equal to y. However, if we have already determined that x is not less than y and not greater than y, it must logically be the case that x is equal to y.

Python provides the else keyword as a "catch-all" for this purpose. By using else, we can handle the final remaining case without asking a redundant third question.

compare.py
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
elif x > y:
    print("x is greater than y")
elif x == y:
    print("x is equal to y")
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
elif x > y:
    print("x is greater than y")
else:
    print("x is equal to y")
By the time the program reaches the final block, the only remaining logical possibility is equality.
Refactoring to use else for the final condition.

Even though modern computers are incredibly fast, this approach is better designed. It reduces the complexity of the program by having fewer "nodes" or decision points. The resulting control flow is more direct and easier for other programmers to read.

user@terminal:~$ python compare.py
What's x? 1
What's y? 2
x is less than y
user@terminal:~$ python compare.py
What's x? 2
What's y? 1
x is greater than y
user@terminal:~$ python compare.py
What's x? 1
What's y? 1
x is equal to y
This flowchart shows how the 'False' path of the second question leads directly to the final result without another diamond.
Minimized logic flow using else.

The or Keyword for Compound Conditions

Sometimes we want to execute a single block of code if any one of several conditions is true. Just like in English, Python allows us to combine questions using the or keyword. This results in a compound Boolean expression that evaluates to true if at least one of its components is true.

Consider a scenario where we only care if x is equal to y or not. We can combine the "less than" and "greater than" checks into a single line to determine non-equality.

compare.py
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y or x > y:
    print("x is not equal to y")
else:
    print("x is equal to y")
Using the or conjunction to check for non-equality.

Visually, this means multiple paths in our logic can lead to the same outcome. If the first part of the expression (x < y) is true, the entire expression is true. If it's false, Python then checks the second part (x > y).

Notice how two different decision nodes point to the same output box.
Flowchart for or logic.

While the or version is correct, we can tighten the design further by using the "not equal" operator (!=). This allows us to ask one single question instead of two combined ones, making the code more succinct and readable.

compare.py
if x < y or x > y:
    print("x is not equal to y")
else:
    print("x is equal to y")
if x != y:
    print("x is not equal to y")
else:
    print("x is equal to y")
Simplifying compound logic with the != operator.

Alternatively, if you prefer to check for equality first, you can simply use the == operator and flip the if and else blocks. Both are equally valid; the choice often depends on which condition feels more natural to emphasize.

compare.py
x = int(input("What's x? "))
y = int(input("What's y? "))

if x == y:
    print("x is equal to y")
else:
    print("x is not equal to y")
Alternative check focusing on equality first.
Note
In Python, the colon (:) at the end of a conditional and the indentation of the following block are mandatory. Python uses indentation levels to define blocks of code, unlike languages like C or Java which use curly braces.

The and Keyword and Range Comparisons

Just as or requires only one condition to be true, the and keyword requires all conditions to be true. This is particularly useful for range comparisons, such as determining a student's letter grade based on a numeric score.

A typical grading scale requires checking both a lower and an upper bound. For example, a score is an "A" if it is at least 90 and at most 100.

grade.py
score = int(input("Score: "))

if score >= 90 and score <= 100:
    print("Grade: A")
elif score >= 80 and score < 90:
    print("Grade: B")
elif score >= 70 and score < 80:
    print("Grade: C")
elif score >= 60 and score < 70:
    print("Grade: D")
else:
    print("Grade: F")
Initial implementation of grade ranges using and.

Python offers a more succinct syntax for this type of range check. Similar to mathematical notation used on paper, you can chain the comparison operators together.

grade.py
if score >= 90 and score <= 100:
    print("Grade: A")
if 90 <= score <= 100:
    print("Grade: A")
This "chained comparison" is more readable and performs the same logic.
Using Python's chained comparison syntax.

We can refine the design even further by relying on the sequential nature of elif. Because the conditions are checked in order, if the program reaches the check for a "B", we already know the score is not 90 or above. Therefore, we don't need to explicitly check if the score is less than 90 in every subsequent step.

grade.py
score = int(input("Score: "))

if score >= 90:
    print("Grade: A")
elif score >= 80:
    print("Grade: B")
elif score >= 70:
    print("Grade: C")
elif score >= 60:
    print("Grade: D")
else:
    print("Grade: F")
The upper bound is implicitly handled by the previous if/elif statements.
Optimized grade logic removing redundant upper-bound checks.

This final version is highly readable and maintainable. It demonstrates how understanding the control flow of if, elif, and else allows you to write more elegant and efficient code.
